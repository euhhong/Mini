# 지시 T1126 — 바위 하나에서 돌이 여러 개 (★재민 11-03 판정 ⓐ)

**세션:** S2 · **베이스:** main(land1041 착지 뒤 · 없으면 그때 main) · **가지:** `batch/rock-yield-1104` · 커밋 `[승인 대기 · T1126]`

## 왜

T1120 실측(「지금 할 일」을 따르는 봇 · 30분 판 둘): 돌괭이 7.3 · 7.6분 · 곡괭이 14.9 · 30.0분 · **첫 움집 0/2**. 바위 하나 = 돌 1(`zone.js lootOfResource` `rock → { stone: 1, pebble: 2 }` · 바위가 **부서질 때 한 번에만** 나온다)이라 곡괭이 5 + 도끼 2 = 바위 일곱을 찾아 걷는 데 30분이 다 간다.

★재민 11-03 판정 **ⓐ** — "바위 = 큰 덩어리"를 몸으로: **칠 때마다 돌이 1개씩 나오고, 바위는 작아지다 다 캐면 사라진다(유한)**. ⓑ 밀도 · ⓒ 레시피 수 · ⓓ 그대로 는 기각.

## 할 일

1. **한 번 칠 때 돌 하나** — 바위 `hp` 가 1 줄 때마다 그 자리에서 `stone 1`(플레이어 `tryGather` · NPC 채집 실행부 `zone.js` "직접 채집" 갈래 둘 다 — **정본 하나**, 사본 금지). 부서질 때 주던 `pebble 2` 는 부서질 때 그대로.
2. **바위 하나 = 돌 몇 개 = 바위 크기에서** — 나무가 `wood 3 + floor(r/3)` 으로 크기 비례인 것과 같은 꼴. 수는 손으로 적지 말고 **돌 1개 무게(`weights.js` stone kg)와 바위 반경 `r`(부피)에서 유도**한다(유도 식 · 근거 한 줄을 보고에). 목표 범위 확인: 마을 근처 흔한 바위 하나 = 돌 3 ~ 5개면 곡괭이(돌 5)가 바위 1 ~ 2개.
3. **보이는 크기** — 남은 `hp` 비율로 바위 그림이 작아진다(클라 `resource_update` 의 hp 를 이미 받는다 · 크기 단계 둘 ~ 셋이면 충분 · 새 그림 0 · 축소 렌더).
4. **NPC 광부도 같은 규칙** — T724(`T724_MINE_ACT` "치는 순간 손에, 귀환하면 곳간에")가 바위를 칠 때 같은 문을 지나는지 확인. 광맥(`ore`)은 이 카드 밖(그대로).
5. 손잡이 `T1126_ROCK_YIELD`(켬 기본 후보 · `=0` = 종전 바이트).
