## §2. 열 배열 — 몸 번호 = 칸

### ⓐ 꼴

* 열: `Float64Array` 둘(`X` · `Y`) — 칸 = **몸 번호**. 번호는 몸이 태어날 때 받아 몸 칸 하나(`_colS`)에 적힌다(리터럴 안 · 몸 필드 규약 `test-body-fields` ⑥).
* 몸 객체의 `x` · `y` 는 **열 칸을 보는 창**이다 — 제 것 접근자 속성(`get` → `X[this._colS]` · `set` → `X[this._colS] = v`). 읽기 481 · 483 · 쓰기 32 · 32 자리가 **한 글자도 안 바뀐 채** 열을 읽고 쓴다(빠뜨림 0 — T738 §3 ⓐ 꼴의 장점 그대로).
* 열을 직접 도는 자리(커널 · 다음 카드)는 창을 거치지 않고 `X[s]` 를 읽는다 — 그것이 "열이 정본" 이다(객체에 사본이 없다 · 모으기 · 흩기가 설 자리가 없다).

### ⓑ 왜 T738 은 느렸고 이 판은 아닌가 — 사전 모드

* T738 증인 판은 리터럴이 지은 **데이터 칸을 그 자리에서** 접근자로 다시 지었다(`defineProperty` · 마지막 칸이 아닌 칸). V8 은 그 꼴을 숨은 꼴 사슬에 못 싣고 **몸을 사전 모드로 내린다**("AccessorsOverwritingNonLast") — 몸 하나하나가 해시 객체가 되어 그 몸의 **모든 칸**(x · y 만이 아니라)을 읽는 자리가 사전 찾기였다. 그것이 +11 % 다.
* 이 판: ① 리터럴에 x · y 를 **안 둔다**(그 자리에 `_colS`) ② 리터럴 바로 뒤에 x · y 접근자를 **새 칸으로 덧붙인다** ③ 접근자 함수는 **모든 몸이 같은 넷**(모듈 함수 · 몸마다 클로저 0). ⇒ 모든 몸이 같은 숨은 꼴 사슬(빠른 속성) — 부른 자리마다 단형이고 V8 이 창을 인라인한다.
* 증거(`test-t1145-xy-col` ①): 615 몸 빠른 속성 · 한 꼴 · ★미끼 둘이 문다 — T738 꼴(그 자리 다시 짓기)은 사전 모드 · 몸마다 다른 클로저는 꼴이 갈린다. 존(②): 주민 몸 408 전부 빠른 속성 · 숨은 꼴 2.
* 다른 것은 **키 차례에서 x · y 가 뒤로 간다**는 것 하나다 — 키 차례를 읽는 자리 0(§1).

## §4. 걸음 WASM 커널(T461)이 열을 직접 도는 꼴

지금(T461 · T672): `_wwPre` 가 걷는 몸마다 `X[i] = p.x; Y[i] = p.y; VX[i] = p.vx; VY[i] = p.vy; RD[i] = …` 로 커널 메모리에 **모은다**(i = 이 틱 커널 목록 차례) → `ww_step(n)` → `_wwPost` 가 `p.x = X[i]; p.y = Y[i]` 로 **흩는다**. 모으기 · 흩기가 몸마다 칸 열 개를 짚는다.

열 정본 꼴:

1. **열을 커널 메모리 위에** — `BodyCols.create({ alloc: (bytes) => _WW.view(bytes) })` 처럼 열 버퍼를 WASM 메모리에서 받는다. 메모리가 자라면(`ensure`) 뷰가 떨어지므로 열 모듈이 `rebind(X, Y)` 를 받는다(창은 모듈의 `X` 를 보므로 그 한 줄로 끝).
2. **커널 입력 = 번호 목록** — `_wwPre` 는 걷는 몸의 **번호**만 `S[i]`(Int32) 에 적는다(갈래 거름은 그대로 — 거름이 짚는 칸은 다음 칸 카드가 열로). `walk.c` `step_one(i)` 의 `X[i]` → `X[S[i]]`(읽기 · 쓰기 둘 다) — 산술 글자 무변 · 견줌(`verify`) 꼴 그대로(JS 정본이 창으로 옮긴 뒤 열과 비트로).
3. **흩기 0** — 커널이 열에 바로 쓴다 ⇒ `_wwPost` 의 `p.x = _WW.X[i]` 두 줄이 사라진다(갈래 `ST` 뒷일만 남는다).
4. vx · vy 가 열이 되면(카드 ㄴ) 모으기도 x · y · vx · vy 넷이 사라진다 — 남는 것은 길 배속 `RD`(`_rdMul × 개울`) 하나.
